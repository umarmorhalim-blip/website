1. Domain Classification & Mapping

Every item in the checklist belongs to one of three architectural layers. Conflating them leads to misrouted fixes — you can't solve a database N+1 with a CDN.

Layer Items
Frontend Optimization Loading skeletons, Debounce input handlers, Split code into chunks, Minify JS & CSS, Add Lazy Loading, Defer non-critical scripts, Unnecessary re-renders ❌, Unused dependencies ❌, Lighthouse audit
Backend & API Performance Load balancer, Compress images, Cache expensive queries, Server-side caching, Compress API payloads, Paginate large lists, N+1 database queries ❌
Database & Infrastructure Index the database, Add CDN, Database connection pooling

2. Technical Mechanics per Item

✅ Load Balancer

Distributes incoming HTTP requests across multiple application server instances. Eliminates single-point-of-failure and increases horizontal throughput. Improves TTFB under high concurrency by preventing request queuing behind a saturated process. Typical setup with Nginx upstream:

# nginx.conf
upstream app_servers {
  least_conn;
  server app1:3000;
  server app2:3000;
  server app3:3000;
  keepalive 32;
}
server {
  listen 80;
  location / {
    proxy_pass http://app_servers;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
  }
}

✅ Index the Database

A full table scan is O(n); a B-tree index lookup is O(log n). Without indexes on columns used in WHERE, JOIN, ORDER BY, the query planner reads every row. Adding a composite index on a 10M-row table can drop a 4s query to 8ms.

-- Before: full scan (seq_scan)
EXPLAIN ANALYZE SELECT * FROM orders WHERE user_id = 42 AND status = 'pending';
-- Seq Scan on orders  (cost=0.00..58901.00 rows=1234)

-- Add composite index
CREATE INDEX CONCURRENTLY idx_orders_user_status
  ON orders (user_id, status)
  WHERE status IN ('pending', 'processing');

-- After: index-only scan  (cost=0.56..8.59 rows=4)

✅ Compress Images

Images are typically 60–80% of page weight. Switching to WebP/AVIF reduces size 30–70% vs JPEG at equal quality. Use <picture> with srcset for responsive delivery. Impact: directly reduces LCP.

<picture>
  <source
    srcset="hero-480.avif 480w, hero-1200.avif 1200w"
    sizes="(max-width: 600px) 480px, 1200px"
    type="image/avif"
  />
  <source
    srcset="hero-480.webp 480w, hero-1200.webp 1200w"
    type="image/webp"
  />
  <img src="hero-1200.jpg" alt="…" loading="lazy" width="1200" height="630" />
</picture>

✅ Loading Skeletons

Replace blank content areas with shimmer placeholders during data fetches. Reduces perceived wait time (CLS impact if sized correctly) and signals activity. The shimmer CSS gradient creates a continuous scan animation at zero JS cost.

// React skeleton component
function SkeletonCard() {
  return (
    <div className="card">
      <div className="skeleton" style={{ height: 200, borderRadius: 8 }} />
      <div style={{ padding: '1rem' }}>
        <div className="skeleton" style={{ height: 20, width: '60%', marginBottom: 8 }} />
        <div className="skeleton" style={{ height: 14, width: '90%' }} />
      </div>
    </div>
  );
}

✅ Cache Expensive Queries

Wrap DB-heavy reads in a Redis/Memcached layer with TTL. Offloads repeated identical queries from the database entirely. Critical for aggregations, leaderboards, or dashboard data that don't need real-time precision.

// Node.js with Redis
async function getDashboardStats(orgId) {
  const key = `stats:${orgId}`;
  const cached = await redis.get(key);
  if (cached) return JSON.parse(cached);

  const stats = await db.query(
    `SELECT COUNT(*) orders, SUM(revenue) total
     FROM orders WHERE org_id = $1 AND created_at > NOW() - '30 days'::interval`,
    [orgId]
  );
  await redis.setex(key, 300, JSON.stringify(stats)); // 5-min TTL
  return stats;
}

✅ Debounce Input Handlers

Without debouncing, a search field fires a network request on every keystroke — potentially 5–10 requests per second per user. Debounce delays execution until input pauses, collapsing bursts into a single call. Reduces API load and prevents race conditions.

// React hook
function useDebounce<T>(value: T, delay = 300): T {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);
  }, [value, delay]);
  return debounced;
}

function SearchInput() {
  const [query, setQuery] = useState('');
  const debouncedQuery = useDebounce(query, 300);
  useEffect(() => { if (debouncedQuery) search(debouncedQuery); }, [debouncedQuery]);
  return <input onChange={e => setQuery(e.target.value)} />;
}

✅ Code Splitting

Route-level and component-level splitting via dynamic import() reduces the initial JS bundle delivered to the browser. Each route becomes an async chunk loaded on demand. Impact: directly reduces FCP and TTI.

// React Router v6 — lazy routes
import { lazy, Suspense } from 'react';
const Dashboard = lazy(() => import('./pages/Dashboard'));
const Settings  = lazy(() => import('./pages/Settings'));

function App() {
  return (
    <Suspense fallback={<PageSkeleton />}>
      <Routes>
        <Route path="/dashboard" element={<Dashboard />} />
        <Route path="/settings"  element={<Settings />} />
      </Routes>
    </Suspense>
  );
}

✅ CDN

A Content Delivery Network serves static assets (JS, CSS, images, fonts) from edge nodes geographically close to each user. Reduces asset RTT from 120–200ms to 5–20ms and offloads bandwidth from origin servers. Configure long Cache-Control with content-addressed filenames.

# nginx — CDN cache headers for immutable hashed assets
location ~* \.(js|css|woff2)$ {
  add_header Cache-Control "public, max-age=31536000, immutable";
  add_header Vary "Accept-Encoding";
  gzip_static on;
}

✅ Server-Side Caching

HTTP-level caching with ETag/Last-Modified, full-page caching in Redis (e.g. Next.js ISR), or reverse-proxy caching in Nginx/Varnish. Serves entire responses without touching application code or DB.

✅ Paginate Large Lists

Returning 10,000 rows in a single API response serializes ~2–10MB of JSON, strains the DB and causes JavaScript render-blocking. Cursor-based pagination (vs offset) avoids the OFFSET n performance trap at high page numbers.

-- Cursor-based (efficient at any depth)
SELECT id, created_at, title
FROM posts
WHERE created_at < :cursor_ts   -- pass last item's timestamp
ORDER BY created_at DESC
LIMIT 20;

-- vs OFFSET (gets progressively slower)
SELECT * FROM posts ORDER BY created_at DESC LIMIT 20 OFFSET 10000; -- 💀

✅ Lighthouse Audit

Automated audit of Core Web Vitals (LCP, CLS, INP), accessibility, SEO and best practices. Run in CI via lighthouse-ci with score budgets to catch regressions before deploy.

✅ Compress API Payloads

Enable Gzip/Brotli on all API responses. Brotli achieves ~20% better compression than Gzip on text. A 400KB JSON response becomes ~30KB, reducing transfer time and data costs for mobile users.

// Express.js
import compression from 'compression';
app.use(compression({ level: 6, threshold: 1024 }));
// or explicit Brotli in Nginx:
// brotli on; brotli_comp_level 6; brotli_types application/json text/html;

✅ Minify JS and CSS

Dead code elimination, whitespace removal and identifier mangling via esbuild/terser/Lightning CSS. Reduces bundle size 30–70%. Run at build time, never at runtime.

✅ Lazy Loading

Browser-native loading="lazy" on images and iframes defers off-screen resource fetching until the user scrolls near them. Reduces initial page weight and unblocks LCP for above-the-fold content.

✅ Defer Non-Critical Scripts

Third-party scripts (analytics, chat widgets, tag managers) can add 200–600ms to TTI. Use defer or async on <script> tags, or load them via requestIdleCallback post-interaction.

// Defer analytics until page is interactive
function loadAnalytics() {
  const s = document.createElement('script');
  s.src = 'https://example.com/analytics.js';
  s.async = true;
  document.head.appendChild(s);
}

if ('requestIdleCallback' in window) {
  requestIdleCallback(loadAnalytics, { timeout: 3000 });
} else {
  window.addEventListener('load', loadAnalytics);
}

✅ Database Connection Pooling

Opening a new TCP connection + TLS handshake + PostgreSQL auth on every query adds 50–200ms of overhead. A pool (PgBouncer, Prisma connection pool) maintains warm connections and serves them to concurrent requests in microseconds.

// Prisma connection pool config (DATABASE_URL)
// postgresql://user:pass@host:5432/db?connection_limit=10&pool_timeout=10

// Or with PgBouncer in transaction mode:
// max_client_conn = 1000
// default_pool_size = 25
// pool_mode = transaction

3. Anti-Pattern Remediation

❌ N+1 Database Queries

Problem: Fetching a list of N records and then making 1 additional query per record = N+1 round trips. 100 posts = 101 queries. At 50ms each, that's 5 seconds of DB time on a single request.

// ❌ BEFORE — N+1 pattern
const posts = await db.post.findMany({ take: 50 });
for (const post of posts) {
  post.author = await db.user.findUnique({ where: { id: post.authorId } });
  // 50 extra queries fired sequentially
}
// ✅ AFTER — Prisma eager loading (1 query with JOIN)
const posts = await db.post.findMany({
  take: 50,
  include: { author: true },  // single JOIN
});

// ✅ AFTER — Manual batching with DataLoader (GraphQL resolvers)
import DataLoader from 'dataloader';
const userLoader = new DataLoader(async (ids: string[]) => {
  const users = await db.user.findMany({ where: { id: { in: ids } } });
  return ids.map(id => users.find(u => u.id === id));
});
// Resolver fires once per batch, not once per field resolution
-- ✅ Raw SQL — explicit JOIN
SELECT p.id, p.title, u.name AS author_name
FROM posts p
JOIN users u ON u.id = p.author_id
ORDER BY p.created_at DESC
LIMIT 50;
-- 1 query, 1 round trip, index-assisted join

❌ Unnecessary Re-renders

Problem: React re-renders a component whenever its parent renders or its props change by reference. Without memoization, an entire subtree rerenders on every state change — even when the output would be identical.

// ❌ BEFORE — re-renders on every parent update
function ParentComponent() {
  const [count, setCount] = useState(0);
  const items = [1, 2, 3]; // new array reference each render

  return (
    <>
      <button onClick={() => setCount(c => c + 1)}>{count}</button>
      <ExpensiveList items={items} /> {/* re-renders every click */}
    </>
  );
}
// ✅ AFTER — memoization + stable references
import { memo, useMemo } from 'react';

const ExpensiveList = memo(function ExpensiveList({ items }) {
  return <ul>{items.map(i => <li key={i}>{i}</li>)}</ul>;
});

function ParentComponent() {
  const [count, setCount] = useState(0);
  const items = useMemo(() => [1, 2, 3], []); // stable reference

  return (
    <>
      <button onClick={() => setCount(c => c + 1)}>{count}</button>
      <ExpensiveList items={items} /> {/* skipped — props unchanged */}
    </>
  );
}

// ✅ State colocation — move state DOWN to avoid wide re-render trees
function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
// Now ExpensiveList is a sibling, not a child of the counter's state owner

❌ Unused Dependencies

Problem: npm packages installed once and never removed accumulate silently. Each ships to the browser (or bloats the server bundle), slows install times, widens the attack surface and adds transitive dependency rot.

# Step 1: Audit unused packages
npx depcheck                   # reports unused deps and missing deps
npx knip                       # finds unused exports, files, types
npx @next/bundle-analyzer      # visual treemap of bundle contents

# Step 2: Audit bundle size
npx bundlephobia <package>     # before adding any new dep

# Step 3: Remove confirmed dead packages
npm uninstall moment lodash uuid  # example dead deps
# moment → date-fns (tree-shakeable, 70% smaller)
# lodash → native ES2022 methods
# uuid → crypto.randomUUID()
# Step 4: Add to CI/CD pipeline (.github/workflows/bundle-check.yml)
name: Bundle Check
on: [pull_request]
jobs:
  bundle:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: npx knip --no-exit-code --reporter compact
      - run: npx depcheck --ignores="@types/*,eslint-*"
      - name: Size limit check
        run: npx size-limit  # fails PR if bundle grows beyond budget

4. Prioritization Matrix — Top 5 ROI

Ranked by impact on Core Web Vitals, throughput under load, and engineering effort required.

1

Eliminate N+1 Queries

Impact: Can reduce API latency by 10–100×. A single undetected N+1 on a high-traffic endpoint will bring a database to its knees under load. Fix it first — it's the most asymmetric return in backend engineering. Use EXPLAIN ANALYZE and your ORM's query logging to find them.

2

Database Indexing

Impact: Transforms O(n) scans into O(log n) lookups. A missing index on a foreign key or filter column is a silent performance bomb that only explodes at scale. Run pg_stat_user_tables to find tables with high seq_scan counts.

3

Code Splitting + Minification

Impact: Reduces initial JS payload delivered to the browser, directly improving FCP, TTI and LCP scores. Shipping a 2MB monolithic bundle when users only need 200KB for the landing page is routine waste. Route-level splitting is often a one-afternoon refactor.

4

Image Optimization + CDN

Impact: Images are the #1 cause of poor LCP scores. WebP/AVIF conversion + srcset + CDN delivery compounds: smaller files delivered from 10ms away. Lighthouse will surface this as a critical LCP opportunity with estimated savings.

5

Server-Side + Query Caching

Impact: A Redis layer in front of expensive queries absorbs traffic spikes without scaling the database. Combine with CDN edge caching for public pages and you can serve 100× the traffic from the same infrastructure. TTL discipline matters — don't cache stale data.

Engineering principle: Optimizations compound. Eliminate N+1s first (reduces DB load), then add indexes (queries become faster), then cache results (eliminates repeat queries entirely). In that order, each step amplifies the previous one.
